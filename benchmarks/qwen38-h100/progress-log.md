## Do not repeat

- Unconditional cuBLAS for all quantized matmul on Hopper: 33% slower at ubatch 128 (MMQ wins 2.3x to 5.7x at n=16). Keep the ne11 gate (256 since P2; 512 before).
- `GGML_CUDA_GRAPH_OPT=1`: +2.4% wall at 10k+1k (17.45 -> 17.87 s). Rejected.
- BF16 cuBLAS compute: +0.27% only, lower input precision. Rejected.
- Judging small decode effects on aggregate wall at concurrency 8: 35.6% within-build spread. Use per-request server decode rate.
- `/slots/{id}?action=erase` does not clear llama-server's host prompt cache. Every request needs a unique tag.

Gate for speculative decoding (planned procedure, not yet executable: no harness script exists and the prompt file `openthoughts-first32.jsonl` lives only on the bench host under `/home/pratik/qwen38-bench/qvac-fabric-llm.cpp/benchmarks/qwen38-h100/`, not in this tree; both are added when D3 starts). Logits-level KL does not apply because the accepted tokens are verified against the target model, so the contract is exact agreement under greedy decoding. Procedure: start the server with and without `--spec-type draft-mtp` (same model, same build), send the 32 prompts with `temperature 0`, `max_tokens 256`, `ignore_eos`, and record the token id sequences. Pass: all 32 sequences identical to the non-speculative run, except sequences whose first divergence is a numerically tied token (top-2 logprob gap below 0.05 at that position in the non-speculative run, obtained with `logprobs 2`); at most 1 of 32 such tied divergences, since the non-speculative build flips 0.003% of top-1 tokens against itself. Throughput is reported separately as accepted tokens per second and mean acceptance length; a speculative config that passes this gate but does not raise output tokens per second on the 10k+1k shape is not accepted.

A change that fails its gate is rejected regardless of speed.

## P4 chunked gated delta net for prefill (2026-09-15)
Status: accepted (`patches/P4-gdn-chunked.patch`)
Current state before this iteration: server Q4 pp10k 4340, pp110k 3164, tg10k 71.3; Q8 pp10k 4692, pp110k 3201 (ub 4096). Fast loop Q4 pp10240 4807.8, Q8 4988.0.
Hypothesis: the serial per-token GDN kernel (`gated_delta_net_cuda`, one dependent step per token, 4.57 ms per layer per 4096-token ubatch = 1.12 us per token-step) can be replaced for prefill by a chunked WY-form kernel (chunk 64) that does the same math as O(C^2 d) matmuls per chunk with the token recurrence only between chunks, cutting GDN time per layer by >= 6x in fp32 without tensor cores.
Why it should work: P1 profile at ub 4096: gated_delta_net is 32.1% (Q4) / 33.6% (Q8) of prefill kernel time, 1976 ms over 432 launches. Per token-step the serial kernel does about 12 FMAs, 2 warp reductions and 8 dependent global loads per lane, i.e. about 2200 cycles at 1.98 GHz for roughly 200 cycles of arithmetic; the chain is latency-bound. The chunked form (S_tilde = S / gamma turns the gated rule into an ungated delta rule; U' = (I + A)^-1 (beta v - beta gamma S0^T k) with A[t][s] = beta_t (k_t . k_s) exp(G_t - G_s); S_C = gamma_C S0 + sum_s exp(G_C - G_s) k_s U'_s^T; o_t = scale (gamma_t S0^T q_t + sum_{s<=t} exp(G_t - G_s) (k_s . q_t) U'_s)) needs about 1.4 M FMA per chunk per 32-column block, 5.6k per thread, with all loads staged in shared memory; 64 sequential chunks per 4096 tokens instead of 4096 sequential steps.
